## 三、红线（所有前端任务书强制）

- **禁止自写棋盘、坐标换算、落子/提子逻辑、变化播放逻辑**；全部使用 WGo.js（已 vendor 于 `frontend/assets/wgo/`）。
- **禁止自研 canvas 图形组件**；找不到成熟库就简化需求。
- 每个前端切片交付必须附 **Playwright 截图**验收证据。

## 四、开发期 API 纪律（铁律 3）

- 逻辑开发一律 mock（¥0）；真实 API 仅限 prompt 迭代（`max_tokens ≤ 400`，禁 reasoner）与阶段验收抽测；
- 相同（prompt 版本+局面）结果必须本地缓存；
- 预算按 `项目书v2.md §6` 里程碑切分，开工前核对余额。

## 五、可维护性横切要求（用户强调：必须留出修 bug / 打补丁 / 更新功能的接口和操作端）

1. **打补丁 → 数据库迁移机制**：`schema_migrations` 版本表 + 增量迁移列表；改表结构只追加迁移，禁止手改旧 SQL（T0 实现）。
2. **修 bug → 运维/诊断 API**：`/health`、`/engine/status|restart`、`/logs`、`/cache/clear`、`/db/backup`、`/version`（T0 实现，详见 `T0-可维护性基座.md`）。
3. **更新功能 → 契约只增不改**：API `/api/v1` 前缀；废弃字段保留一个小版本再移除；每次契约变更同步更新 `frontend/js/api.js` 封装。
4. **更新功能的操作端**：
   - 前端预留「设置/诊断」页入口（引擎后端切换、清缓存、版本与 schema 显示）；
   - `PUT /system/settings` 配置热更新（已有）→ 发布新功能开关用；
   - 桌面 exe 带语义化版本号，`/system/version` 供「检查更新」；PyInstaller 打包注入版本（T7）。
   - 讲解缓存 key 必须含 prompt 版本号，升级 prompt 后可用 `/cache/clear` 强制刷新（T4 注意）。

## 六、GPU/CPU 适配总要求（用户强调）

- 目标：**电脑无论有没有 GPU 都能用**。
- 方案：`engine/katago-opencl.exe`（OpenCL，有核显/独显优先）+ `engine/katago-eigenavx2.exe`（纯 CPU 回退）。
- 后端启动/首次使用时**自动探测**：OpenCL 不可用则回退 eigenavx2，结果写入 config（`katago.backend: auto|cpu|opencl`），支持手动强制。
- 探测必须**快速**：不得触发 KataGo 的 OpenCL kernel 编译（首次约 5 分钟），需用轻量探测（如 `katago version` 子命令或加载探测）。
