# T0 任务书：可维护性基座（后端，横切 W0/W1）

> 用户硬性要求：**必须留出后续修 bug、打补丁、更新功能的接口和操作端。**
> 本任务与 T1（GPU/CPU 适配）同属后端，由同一 agent 合并完成（避免文件冲突）。

## ① 做什么

### 1. 数据库迁移机制（打补丁的地基）
- `backend/common/db.py` 增加版本表 `schema_migrations(version INTEGER PRIMARY KEY, applied_at TEXT)`；
- `init_db()` 改为：基线建表（现有 SCHEMA_SQL 记为 version 1）→ 按 `MIGRATIONS` 列表（`[(2, "ALTER ..."), (3, "..."), ...]`）依次执行未应用迁移；
- 约定写入 `docs/architecture.md` §3：后续任何改表结构只追加迁移脚本，禁止手改旧 SQL。

### 2. 运维/诊断 API（操作端，`backend/routers/system.py` 扩展）
在现有 `/api/v1/system/info`、`/settings` 基础上新增：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/system/health` | 四状态：数据库连通、引擎进程存活、模型文件存在、DeepSeek key 配置 |
| `GET /api/v1/system/engine/status` | 引擎当前后端（opencl/eigenavx2）、进程状态、最近错误 |
| `POST /api/v1/system/engine/restart` | 重启引擎（修 bug/换模型后生效），body 可选 `{"backend":"cpu"}` 临时切换 |
| `GET /api/v1/system/logs?lines=200` | 最近服务日志（新增简单文件日志：`server.log_file` 配置，默认 `data/app.log`） |
| `POST /api/v1/system/cache/clear` | 清讲解缓存（prompt 更新后强制刷新），参数 `{"kind":"coach|review|all"}` |
| `POST /api/v1/system/db/backup` | SQLite 备份到 `data/backups/goapp-YYYYMMDD-HHMMSS.db`（VACUUM INTO），返回路径 |
| `GET /api/v1/system/version` | 版本 + 引擎后端 + 契约版本（前端"检查更新"用） |

- `SystemInfoResponse` 扩展：`engine_backend`（当前所选后端）、`schema_version`；
- 所有新接口补充 `docs/architecture.md` §4.4 契约与字段示例（铁律 5）。

### 3. 契约版本化约定（接口预留）
- 契约文档 §7 增补：**API 只增不改**；废弃字段至少保留一个小版本（x.y 的 y+1）再移除；所有新端点在 `frontend/js/api.js` 同步封装。

## ② 禁止做什么

- 禁止改已有端点（`/info`、`/settings`、复盘/教练/题目）的请求/响应字段（只能增加字段）；
- 禁止用破坏性方式改表结构（必须走迁移脚本）；
- 禁止把日志写进 data 之外随意路径、禁止日志无限增长（需简单轮转，如 >5MB 归档一个备份）；
- 不引入新第三方依赖（标准库 + 现有依赖即可）。
