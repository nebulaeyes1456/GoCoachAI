# T2 任务书：前端 M0 棋盘命门（W4）

> 项目命门：**不过关项目不继续**。必须用成熟开源库 WGo.js，禁止自研任何棋盘/坐标逻辑。

## ① 做什么

用 WGo.js 在 `frontend/` 从零搭建**最小复盘闭环**（M0 验收目标）：

1. **复盘页 `index.html`**（现代美观 UI，纯 ESM + 无构建）：
   - 载入 SGF：内置一个 9 路示例棋谱（数据可来自 `frontend/js/mock.js` 改造后）+ 文本框粘贴任意 SGF；
   - **棋盘渲染**：用 `WGo.Board`（支持 9/13/19 路自适应）；
   - **落子序列与定位**：手数列表/滑块，点击定位到某一手（用 WGo.Kifu / WGo.Player 能力）；
   - **播放控制**：前进/后退/播放全部（WGo.Player）；
   - **变化播放**：主变化可播放；
   - **胜率曲线**：用 mock 数据绘制（曲线非棋盘，允许 canvas/SVG 自绘）。
2. **修复 `frontend/js/mock.js`**：其依赖缺失的 `coord.js`（v1 残留，且违反红线）。坐标/落子一律改用 WGo.js（如 `WGo.sgf` 解析、`WGo.Board` 内部坐标），**禁止自写坐标换算**。
3. **Playwright 自检脚本**：`scripts/playwright_m0.py`——自动打开页面 → 加载 SGF → 截图（棋盘+棋子）→ 点击第 N 手定位 → 截图 → 播放后截图；输出截图到 `docs/tasks/evidence/`。
4. **预留「设置/诊断」入口**（可维护性要求）：页面顶部预留齿轮入口（M0 可只放占位面板），展示：版本号、引擎后端（opencl/cpu/auto，来自 `/system/info`）、schema 版本；`frontend/js/api.js` 同步封装 `/system/health`、`/system/settings`、`/system/engine/restart`、`/system/cache/clear` 等运维接口（T0 提供）。

## ② 禁止做什么（红线）

- **禁止自写棋盘、坐标换算、落子/提子逻辑、变化播放逻辑**——全部用 WGo.js；
- 禁止引入 Node/构建流程（本仓库无 Node 依赖，纯静态 + ESM）；
- 禁止复用 v1 任何前端棋盘代码（v1 前端已废弃清空）；
- 禁止真实调用 DeepSeek API（M0 用 mock，¥0）。

## ③ 验收方式

- [ ] 浏览器打开 `frontend/index.html` 或经后端 `http://127.0.0.1:8765/`：棋盘渲染正确（9/13/19 路均正常），棋子无偏移/残留；
- [ ] Playwright 脚本跑通并产出截图到 `docs/tasks/evidence/`（至少 3 张：初始、点击第 12 手定位、播放中）；
- [ ] 交互清单人工核对：载入 SGF → 棋盘显示 → 手数定位 → 播放/暂停 → 回退；
- [ ] 代码检查：无自研棋盘/坐标逻辑，全部走 WGo.js API；
- [ ] 胜率曲线随播放联动（移动端/桌面均可用）。
